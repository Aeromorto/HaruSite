HARU · Version 5.5 · 6 September 2026

Issues found and fixed.

v5.5 keeps the original catalogue, photography, themes and languages, with fixes to the bag, checkout behavior, privacy, accessibility and delivery lookup. The original v5 remains at its existing address.

Checkout and privacy

  • Fake email verification: any six digits previously passed. The simulated checkout is replaced with a clear notice that online purchases are unavailable.
  • False order completion: payment failures could open the completion screen. v5.5 never claims payment or order success and keeps the bag intact.
  • Unnecessary personal data: v5.5 no longer asks for or stores checkout names, full addresses, verification codes or order drafts.
  • Data in page URLs: forms now stay disabled until JavaScript handlers are ready, preventing native GET submissions when scripts fail.

Bag reliability

  • Malformed saved bags: unknown and inherited product IDs are rejected; quantities must be finite integers, duplicates are merged, and each product is limited to nine units.
  • External mutation: the cart API returns copies, so callers cannot silently change internal quantities.
  • Blocked or full storage: the bag stays usable in the current tab and explains when changes cannot be saved.
  • Cross-tab state: ordinary changes synchronize between tabs. The v5.5 bag and device-only email list use their own storage keys; v5 data and cookies are left untouched.

Keyboard and navigation

  • Modal focus: the bag has dialog semantics, isolates the background, keeps Tab focus inside, and restores focus when closed.
  • Quantity editing: keyboard focus survives updates and removals. Buttons have translated action/product labels and totals are announced.
  • Navigation: the mobile menu closes with Escape or an outside click; generated bag links preserve language and theme.
  • Presentation: hidden panels stay hidden; focus outlines, reduced-motion rules and no-JavaScript guidance are improved. Unconfigured social links are removed.

Delivery lookup and email form

  • Out-of-order CEP results: new searches cancel old requests; stale responses are ignored and editing the field clears old results.
  • Requests that never finish: an eight-second timeout releases the loading state. Invalid state/city responses and network errors remain recoverable.
  • Third-party script execution: the JSONP fallback is removed; address lookup uses JSON fetch only.
  • Misleading delivery prices: fixed prices and dates are explicitly labeled illustrative, rather than carrier quotes.
  • False newsletter success: the form clearly saves only on this device and reports storage failures; it does not claim a subscription.

Validation and remaining limitations

14 DOM regression tests cover the v5.5 interactions and error cases. The build validates both versions' pages, local assets and fragment links. GitHub runs the tests and build before the workflow deployment.

Real purchases still need an authentication, inventory, order and payment backend. The newsletter has no delivery service, shipping rates remain illustrative, and product certification/health claims still need supporting evidence. Simultaneous localStorage writes can still race. Browser rendering and real-device testing are not covered by the DOM tests.
